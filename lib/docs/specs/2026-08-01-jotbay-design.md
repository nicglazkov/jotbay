# Jotbay — Design

Date: 2026-08-01
Status: approved

## Problem

Markdown context handed to an AI assistant lives on many machines across all
three desktop operating systems, on networks that have nothing to do with each
other. It must converge automatically, be manageable from a terminal, and be
manageable from a polished GUI on every platform.

Latency tolerance is minutes, not seconds. A private git repository is an
acceptable store. The design deliberately does not depend on the machines
sharing a network, a VPN or a mesh — HTTPS to the remote works from anywhere.

## Architecture

A single Rust core crate owns all sync logic. Everything else is a front end.

```
        ┌──────────────── lib/core (Rust) ────────────────┐
        │  git ops · conflict policy · status refs        │
        └───────┬──────────────┬──────────────┬───────────┘
                │              │              │
         jotbay CLI        Tauri GUI      Swift GUI
        (Rust bin)     (links core)   (shells `jotbay --json`)
         + TUI dash    Win + Linux     macOS + menu bar
                        + tray
```

Rust is required for Tauri regardless, so the core adds no toolchain. The
alternative — reimplementing conflict rules in bash, PowerShell, Swift and Rust —
guarantees drift. The Swift app shells out to `jotbay --json` rather than using
FFI: less efficient, far less to break.

## Repository layout

```
jotbay/
├── Jotbay.app          macOS launcher      ┐ generated by the
├── Jotbay.lnk         Windows launcher    │ installer,
├── jotbay.desktop     Linux launcher      ┘ gitignored
├── README.md
├── data/                     the synced notes — desktop shortcut target
├── install/                  install.sh, install.ps1, uninstall.*
├── lib/
│   ├── core/                 Rust sync engine
│   ├── cli/                  jotbay CLI + TUI dashboard
│   ├── gui-macos/            SwiftUI app + MenuBarExtra
│   ├── gui-tauri/            Windows + Linux GUI and tray
│   ├── icons/                source SVG and generated icon sets
│   └── docs/                 this spec
└── .github/workflows/        release pipeline
```

Root launchers are machine-generated and gitignored so a Mac never carries a
stray `.lnk`. `data/` is the only directory whose contents are user data; the
rest is program.

## Sync algorithm

One pass, idempotent, safe to run concurrently (guarded by a lock directory):

1. Acquire lock. Abort if a previous run left a rebase in progress.
2. Stage and commit local changes under `data/` and program changes alike.
   Automated commits are made with signing disabled — see Signing below.
3. Fetch `main` and all `refs/jotbay-status/*`.
4. Rebase onto upstream only when `git rev-list --count @..@{u}` is non-zero.
   Comparing `@` to `@{u}` instead would fire whenever the local branch is
   merely *ahead*, turning every ordinary edit into a pointless rebase.
5. On conflict, apply the keep-both-sides policy and continue.
6. Push `main`. On rejection, fetch/rebase once and retry.
7. Write and force-push this node's status blob.

## Conflict policy: keep both sides

Sync must never stall and must never lose a byte.

On a rebase conflict, for each conflicted path:

- The **upstream** version keeps the canonical filename.
- The **local** version is written alongside as
  `<stem>.conflict-<hostname>-<UTC timestamp>.<ext>`.
- Both are staged; the rebase continues.

Critical detail: during a rebase git replays *your* commits on top of upstream,
so `HEAD` is upstream. `--ours` therefore means the remote and `--theirs` means
your local change — inverted from every intuition. This is the single most
likely place for the implementation to be silently wrong, so it is covered by a
dedicated test that asserts content, not just exit status.

Binary-safe: resolution uses `git show :2:` / `:3:` stage blobs rather than
parsing conflict markers, so it works on any file type.

## Node status

Each node force-pushes a JSON blob to `refs/jotbay-status/<hostname>`.

Per-node refs mean two nodes can never conflict, and `main` carries only
content — no heartbeat commits. A single
`git fetch origin '+refs/jotbay-status/*:refs/jotbay-status/*'` retrieves every
node's state.

Payload:

```json
{
  "hostname": "macbook-pro-14-3",
  "os": "macos", "arch": "aarch64",
  "agent_version": "0.1.0",
  "last_sync": "2026-08-01T19:42:11Z",
  "head": "0e43b35…",
  "ahead": 0, "behind": 0,
  "dirty": 0,
  "conflicts_resolved": 0,
  "last_error": null
}
```

Staleness is derived at read time: a node whose `last_sync` is older than three
sync intervals is shown as stale. Nothing expires the refs; a decommissioned
machine is removed with `jotbay nodes --forget <hostname>`.

## Surfaces

**CLI** — `jotbay status | sync | push | pull | log | nodes | resolve | dash`.
Colored tables, spinners, and a `--json` mode consumed by the Swift app.
`jotbay dash` is a live TUI dashboard.

**macOS** — SwiftUI management window plus a `MenuBarExtra` agent showing sync
state and a manual sync item. Menu-bar glyphs are monochrome template images so
they adapt to light/dark and tinting.

**Windows and Linux** — one Tauri application providing the same window and a
system tray icon.

## Distribution

GitHub Actions builds macOS (arm64 + x86_64), Windows (x86_64) and Linux
(x86_64) on every tag and publishes to GitHub Releases. Installers detect
OS/arch, fetch the matching asset, register the scheduler, create the root
launcher, and place a desktop shortcut to `data/`.

Rationale: the Windows box and every Linux host lack a Rust toolchain, and
installing one on a machine that would otherwise never need it is a poor trade
for a 9-minute first install.

## Scheduling

| Platform | Mechanism | Interval |
|---|---|---|
| macOS | LaunchAgent | 600 s |
| Linux | systemd user timer + `enable-linger` | 10 min, `Persistent=true` |
| Windows | Scheduled Task | 10 min |

`Persistent=true` and `StartWhenAvailable` matter for the laptops that roam
between houses: they catch up on wake instead of waiting a full interval.

## Signing

The global git config sets `commit.gpgsign = true` with SSH signing, and it
works headless. Automated sync commits nonetheless disable signing: if the key
ever gains a passphrase, a scheduled job would block on a prompt that has no UI,
holding the sync lock forever and converting a visible error into silent sync
death. Manual commits sign normally.

## Non-goals

- Real-time sync. Minutes is the accepted latency.
- Multi-jotbay support.
- Mobile clients.
- A Linux GUI on headless servers beyond what the single Tauri build provides.
